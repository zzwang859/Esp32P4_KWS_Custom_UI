# KWS Studio · 关键词采集工作台

基于 **pygame + sounddevice + numpy** 的桌面关键词工作台，提供本地训练和 HID 设备配置两种模式。pygame 负责界面和实时波形，sounddevice 负责后台采集，hidapi 负责设备通信，系统文件夹选择器由 Python 自带的 tkinter 提供。

## 启动

先在本项目根目录运行 `uv sync --locked`，创建或同步唯一的 `.venv`（Python 3.12）。以下命令统一使用 Windows Git Bash 格式，调用这个 Windows 虚拟环境。在本项目根目录运行：

```bash
./.venv/Scripts/python.exe run.py
```

Windows 环境的 `torch` 和 `torchaudio` 通过 uv 显式绑定到 PyTorch 官方 CUDA 12.6 源，锁定版本为 `2.8.0+cu126`。安装包自带 CUDA 运行库，正常训练无需另装 CUDA Toolkit；本机 RTX 2070 与 NVIDIA 595.97 驱动已验证可用。`nvidia-smi` 中的 CUDA 版本表示驱动支持上限，不必与 PyTorch 的运行库版本一致。无可用 NVIDIA GPU 时，训练仍会自动使用 CPU。

同步环境后可检查 GPU（应输出 `2.8.0+cu126 12.6 True`）：

```bash
./.venv/Scripts/python.exe -c "import torch; print(torch.__version__, torch.version.cuda, torch.cuda.is_available())"
```

指定工作区：

```bash
./.venv/Scripts/python.exe run.py --workspace "D:/我的关键词项目"
```

也可以通过模块入口启动：

```bash
PYTHONPATH=src ./.venv/Scripts/python.exe -m kws_custom_ui
```

未指定 `--workspace` 时自动打开上次关闭时的工作区；首次启动或记忆的工作区无法打开时，使用启动目录下的 `workspace/test`，不存在时自动创建。`--workspace` 可优先指定其他工作区。默认窗口为 1280 × 900，可调整大小，最小 1100 × 740。

成功切换本地工作区或正常关闭程序时，会将本地工作区绝对路径记录到项目根目录的 `.kws-studio.json`；设备模式不会覆盖该记忆。未应用的路径输入和失败的切换不会改变记录。

设备搜索条件也保存在 `.kws-studio.json` 的 `hid_device` 中：

```json
"hid_device": {
  "vid": "0x303A",
  "pid": "0x8003",
  "usage_page": "0xFF00",
  "usage": "0x0001"
}
```

支持带 `0x` 前缀的十六进制字符串或十进制整数，四项条件需同时匹配。终端 VID/PID 变更后修改对应值，再切换到设备模式或点击连接重试即可生效，无需重启软件。缺失的字段沿用上述默认值；配置值无效时提示连接失败。保存工作区记忆会保留这些搜索设置及其他配置项。

静音和非静音噪声的录音时长在同一文件的 `recording` 中配置，单位为秒：

```json
"recording": {
  "silence_seconds": 60,
  "noise_seconds": 3
}
```

两项均须为正整数；缺失时分别默认 60 秒和 3 秒。修改后在下次开始对应录音时生效，界面时长与保存的 WAV 长度同步更新。关键词录音仍固定为 2 秒。

## 使用

- **模式切换**：顶部左右拨动开关，左侧“本地训练”、右侧“连接设备”，默认本地训练。录音、训练或模型传输期间不能切换。本地模式中录音、颜色、快捷键、flags 和 PC 仿真参数只保存在 PC，使用 PC CPU/CUDA 训练。设备模式固定使用 `workspace/device`，隐藏录音、麦克风、训练、模型导入及类别增删入口，读取设备的类别文本、颜色、快捷键、flags 和 KWS 滤波参数；类别文本只读，颜色/快捷键/开关及 KWS 参数的修改自动下发到设备。连接失败或断线时开关显示红色“连接失败”，可点击重试；切回本地模式恢复原 PC 工作区。
- **工作区**：手工输入路径后按 Enter 或点击“应用”，也可点击“选择文件夹”。切换前自动保存当前工作区。
- **选择麦克风**：可选择系统默认输入，或从设备列表选择指定麦克风；列表支持滚轮。
- **动作开关**：“关键词素材”栏的总按钮仅控制所有行 `flags` 的 bit0，保留各行灯效、键盘设置。只有所有行的 bit0 都为 1 时，总按钮为绿色并显示“禁用全部快捷键”，点击清零全部 bit0；否则为灰色并显示“启用全部快捷键”，点击置位全部 bit0。每行按钮只同时控制该行 bit1、bit2：三个位全部为 1 时为绿色、显示“禁用”，点击清零 bit1、bit2；否则为灰色、显示“启用”，点击置位 bit1、bit2。bit0 关闭时，行按钮仍显示灰色，不能绕过动作总开关。状态自动保存；新行默认开启 bit1、bit2，bit0 跟随当前总按钮状态，空工作区首行默认三位全开。禁用保留组合键、HID 报文、素材和训练类别。本地模式只保存到 PC；设备模式写入设备并回读确认。
- **录制静音素材**：采集环境底噪，默认录满 **60 秒**自动保存；中途点击“取消本次录音”会丢弃本次采集，不会留下不完整的 WAV。时长可在 `.kws-studio.json` 中配置。
- **非静音噪声素材**：位于背景静音素材下方，默认每次录制 **3 秒**，自动保存到当前工作区 `unknown/`，对应训练类别 index 1。提供实时波形、时长/进度、独立素材数量和“打开目录”按钮；可取消录音，中途取消不保存不完整 WAV。与静音、关键词录音共用麦克风，同一时间只录制一项，训练期间不可录音。噪声份数不计入关键词素材数量，时长可在 `.kws-studio.json` 中配置。
- **关键词列表**：默认四行；点击行选中，再通过顶部“删除行”删除。显示序号自动连续更新，其他行的目录名保持不变；被删除行的空目录直接移除，有内容则重命名为 `delete-时间戳-keywordn`。支持添加行、滚轮和拖动滚动条。
- **关键词录音**：每次固定 **2 秒**，自动结束并保存，支持取消。录制时显示实时波形、音频时长和进度；同一时间只允许一项录音。
- **文本输入**：关键词输入最多 16 个字符，输入框已缩短。支持中文输入法、光标移动、Home/End、Shift 选择、Ctrl+A/C/X/V 和 Tab 切换（关键词 → 组合键 → 下一行）。文本编辑后自动保存；旧工作区已有的超长文本保留，避免截断训练类别名称。
- **组合键输入**：每行可填写 `a`、`{F12}`、`{CTRL}+a` 等组合，自动转换为标准 8 字节 HID 键盘按下报文，随行配置保存。设备端松键统一使用 8 字节全零报文，不单独保存或下发松键字段。无效输入标红，聚焦时在底部显示原因；编辑中的文本仍会保存，对应报文置为 `null`。
- **LED 响应颜色**：点击行内颜色块打开色板，拖动色相条与明度/饱和度色板，或选取预设颜色，再点击“应用颜色”。主界面只展示色块。
- **素材数量**：每秒统计对应目录中 `.wav` 文件数量，包括从外部复制进去的文件；“打开”按钮直接打开对应目录。
- **训练步数**：底部文本框填写正整数，初始值取自 `src/ds-tc-resnet/config.yaml` 的 `train.steps`（当前为 3000）；开始训练后锁定该输入框。
- **开始/停止训练**：保存当前行文本后，在后台依次训练、导出 ONNX、核对 ONNX、转换 ESP32-P4 模型，自动启动 TensorBoard 并打开浏览器。开始后按钮变为“停止训练”，直到全部转换完成才恢复。点击停止后等待当前批次结束，保存已完成步骤的 `latest.pt` 并退出；后续导出、校准和量化阶段不再启动。在转换中点击停止也会终止当前转换，保留上一份成功模型。等待停止时显示“正在停止…”。任务期间禁用切换工作区、录音、增删条目及重复启动。
- **历史训练**：点击“开始训练”时，无历史则直接全新训练；有历史则弹窗选择“接续最近训练”或“清空并重新训练”，也可取消。接续按运行目录时间戳选择最近一次有权重的历史，优先使用 `latest.pt`，其次为编号最大的 `step_n.pt`，最后为 `best.pt`。输入步数表示本次追加的步数，例如历史到第 10 步、输入 10，会继续到第 20 步。只有日志而无任何权重时无法接续。选择“清空并重新训练”会先关闭相关后台服务，再清空当前工作区 `training/` 和 `esp32p4-dl/` 中的全部内容，包括旧权重、ONNX、训练日志、ESP32-P4 模型、转换记录和 `latest.json`；录音、行文本及快捷键配置保持不变。
- **训练状态**：底部按实际设备显示 `训练中(cpu):...` 或 `训练中(cuda):...`；设备尚未选定时显示准备训练状态。
- **导入模型到设备**：本地模式中点击后检查当前工作区最近成功转换的 INT16 模型及 KWS 参数，经 HID 上传完整模型和类别表、激活，再下发 LED 颜色、快捷键及 flags、保存绑定，最后下发 `workspace.json` 的 `kws_filter` 并回读确认。设备固件要求冷却时间至少 1 ms、稳定帧至少 1；旧配置中的 0 值会在上传前明确拒绝。训练模型、MFCC 系数、98 帧滑动池化及 6 对状态接口已固定为设备契约；旧版 7 对状态/功率谱 MFCC 的历史需重新训练，旧产物仍会被拦截。具体约束与验证见 [设备协议说明](docs/device-protocol.md)。设备工程未修改。

## 训练与 ONNX

固定类别顺序为 `index 0 = silence/`、`index 1 = unknown/`，其余类别按 `workspace.json` 的 `rows` 顺序从 index 2 开始，对应各行 `keywords/keywordn/`。类别显示名使用行文本，空文本使用目录名；类别名称必须唯一。静音直接使用 `silence/` 内的真实 WAV，所有类别都必须有录音。未列入配置的目录及 `delete-*` 归档不参与训练。

每次训练独立保存到 `<工作区>/training/<时间戳>/`，包含 `classes.json`（类别 index、名称、源目录及行 ID）、`labels.txt`、`config.yaml`、训练/验证清单、`training.log`、`best.pt`、`latest.pt`、TensorBoard 日志及 `onnx/ds_tc_resnet.onnx`。源录音不复制、不修改。训练结束后会用真实关键词音频核对 PyTorch 与 ONNX 输出，并写入 `verification.json`。工作区在位置和增益增强后按每类切片数分配约 80% 训练集、20% 验证集；无独立测试集，测试流程使用验证集。

接续训练保留原历史，并另建一个运行目录；恢复模型、优化器及累计步数，沿用历史模型结构、特征配置，同时重新读取当前语料。类别顺序、文本或目录映射改变时会拒绝接续，需选择重新开始训练，避免权重与类别含义错配。

ONNX 验证通过后自动使用项目根目录 `.venv` 中的 ESP-PPQ 转换为 ESP32-P4 的 **INT8（w8a8）与 INT16（w16a16）** 模型，默认选择 INT16。界面、预处理、训练、ONNX 导出和量化共用同一份 uv 环境，子进程沿用训练解释器；不再读取 `KWS_ESPDL_PYTHON`。依赖统一维护在根目录 `pyproject.toml` 和 `uv.lock`，运行 `uv sync --locked` 即可安装。ESP-PPQ 1.3.11 使用仓库内的 wheel，当前统一使用 Python 3.12、PyTorch 2.8 和 ONNX 1.17。

ESP32-P4 转换产物使用独立目录，全部保存在当前工作区 `esp32p4-dl/<训练时间戳>/` 中，参照工具链的 `models/`、`output/`、`work/` 结构：`models/` 保存本次 ONNX 副本、静态准备模型、标签、类别映射、MFCC 参数及输入输出映射；`output/w8a8/` 和 `output/w16a16/` 保存 `.espdl`、`.info`、量化 `.json` 和对照报告，`output/` 同时保存两种模型副本与分阶段日志，`conversion.json` 保存转换记录。`esp32p4-dl/latest.json` 指向最后一次成功转换，默认模型位置为其中的 `model` 字段（相对于 `esp32p4-dl/`）。转换产物不写入 `training/`。

校准只读取本次训练清单中各类别的样本（直接复用缓存 MFCC，含生成的白噪声），不读取删除归档和未配置目录；使用完整流式历史状态校准，并比较量化模型的逐块与最终输出。验证优先使用验证/测试清单；小工作区没有独立样本时会在报告中记录使用训练样本的类别。准备后的浮点模型必须通过源 ONNX 一致性检查。类别 index 与训练保持一致。当前 ONNX 的输入是 **MFCC 特征和外部状态**，板端使用 `models/frontend.json`、`frontend.npz` 和 `io_mapping.json` 对接，不能直接输入原始 PCM；实际 ESP-DL 张量布局及测试值见 `.info`。这一步生成模型，不编译或烧录固件。

仅在两种精度转换和 PC 对照均完成后才更新 `latest.json`。失败或停止会保留分阶段日志与中间文件，已有的上一份成功结果保持可用。选择“清空并重新训练”时会在启动新任务前同时清空 `training/` 和 `esp32p4-dl/`；接续训练保留原有训练及转换历史。

Windows 训练与导出会优先加载 Python 虚拟环境中 `msvc-runtime` 提供的 C++ 运行库，避免旧版系统运行库导致 DLL 初始化或 ONNX 检查崩溃。

按原训练代码的定义，`steps` 表示优化步数，不是遍历完整数据集的 epoch 数。命令行运行 10 步训练及导出：

```bash
./.venv/Scripts/python.exe src/ds-tc-resnet/workspace_train.py --workspace workspace/mini_speech_commands --steps 10
```

TensorBoard 只监听本机地址，优先使用 6006 端口，占用时自动寻找可用端口；地址及进程 ID 保存在运行目录的 `tensorboard.json` 中。界面运行期间，训练完成或停止后 TensorBoard 保持运行以便查看曲线。退出界面时会先停止尚未完成的训练、保存已完成步骤的权重，再回收本次界面启动的所有训练、导出及 TensorBoard 进程，释放日志文件占用；浏览器保留打开，服务停止后页面不再更新。Windows 使用系统进程作业管理这些后台进程，界面被强制结束时也会自动回收，不影响其他程序的 Python/TensorBoard 实例。

训练和验证按批次检查停止请求；若原生代码或导出阶段持续不响应，后台会在等待 5 秒后终止当前子进程，此时保留之前已保存的权重。独立命令行 `workspace_train.py` 的 TensorBoard 仍由调用方管理；`--no-browser` 可跳过自动打开浏览器。

每次开始训练前，无论全新训练、清空重训或接续训练，都会重新扫描当前 WAV，强制重新执行 Silero VAD v6 定位、位置/增益增强和 MFCC 批量预处理，结果保存在工作区 `training/<本次训练日期时间>/preprocess/`。Silero 官方 v6.0 源码和 TorchScript 模型保存在 `src/silero-vad`，运行时离线加载。每条关键词录音前后各拼接从 `silence/` 录音抽取的 2 秒素材后再检测；Tstart/Tend 扣除前置 2 秒，并裁定在原始录音范围内，附加素材中的独立语音不计入结果。关键词字典保存于 `preprocess/keywords/keywordn/vad.json`，记录原始坐标下的语音段、填充素材来源及概率序列；预处理报告为 `report.md`。每条关键词录音还会按原始录音坐标导出 `[Tstart, Tend)` 语音段，保存为 `keywords/keywordn/原录音名.wav`，每个关键词独立文件夹；音频为 16 kHz、单声道 PCM16，保留原幅度，不包含附加的静音素材，不加增益或补齐到 1 秒，无语音录音不导出。`speech_clip` 记录文件路径和采样边界。每次训练独立保存预处理结果；接续训练使用新运行目录中的结果，保留原历史；清空重训随训练历史一起清理。训练期间直接读取本次生成的 MFCC，不再逐批解码 WAV 或计算 MFCC。静音生成 1000 份（500 份随机增益），unknown 按 1 秒窗口、20 ms 步进扫描，并增加 100 份随机增益白噪声。关键词切片按 Tend 相对原录音时长选取，起点为负时用原录音末尾补齐，兼容 2 秒和 3 秒关键词录音。完整规则见 [预处理说明](src/ds-tc-resnet/readme.md#工作区-mfcc-预处理)。

## 文件与音频

```text
workspace/test/
├── workspace.json          # 行文本、组合键及 HID 报文、稳定 ID、目录名、LED RGB、KWS 参数、音频规格
├── silence/                # 静音素材（默认每份 60 秒）
├── unknown/                # 非静音噪声/非关键词素材，默认每次录制 3 秒，训练 index 1
└── keywords/
    ├── keyword1/           # 该行所有关键词录音，新录音为 2 秒
    ├── keyword2/
    ├── delete-20261019-153000-123456-keyword3/  # 已删除条目的归档
    └── ...
```

`workspace.json` 的 `rows` 中，每条记录的 `directory` 与 `text` 维护文件夹和行文本的对应关系。例如下面的记录表示 `keywords/keyword1/` 对应文本“打开台灯”（其余字段省略）：

```json
{
  "directory": "keyword1",
  "text": "打开台灯",
  "shortcut": "{CTRL}+a",
  "flags": 7,
  "hid_report": [1, 0, 4, 0, 0, 0, 0, 0]
}
```

编辑行文本后，对应记录的 `text` 自动保存；重新打开工作区时按记录中的 `directory` 恢复关联。新增条目会保存新的对应关系，删除条目会移除该记录，其他条目的关联保持不变。

每行使用一个整数 `flags`（0～255）保存动作开关：

| 位 | 掩码 | 含义 |
|---|---|---|
| bit0 | `0x01` | 动作总开关，控制该关键词是否执行灯效和按键 |
| bit1 | `0x02` | 灯效开关 |
| bit2 | `0x04` | 键盘开关 |

行按钮状态为 `(flags & 0x07) == 0x07`；总按钮状态为所有行 `(flags & 0x01) != 0` 的逻辑与，空列表时按钮不可操作。总按钮只设置或清除 `0x01`，行按钮只设置或清除 `0x06`；bit3～bit7 保留原值。关闭总开关再打开，会恢复各行此前的灯效、键盘设置。总开关关闭时点击灰色行按钮，只能置位该行 bit1、bit2，待总开关打开才生效。

设备端执行灯效需同时满足 bit0、bit1；执行按键需同时满足 bit0、bit2，且 `hid_report` 有效。禁用不会移除该关键词的训练类别。新配置默认 `flags=7`；旧配置的 `enabled=true/false` 分别迁移为 `7/0`，保存时只保留 `flags`。若两字段同时存在，以 `flags` 为准。

组合键语法：普通键直接填写，如 `a`、`b`、`1`；控制键使用花括号，如 `{CTRL}`、`{SHIFT}`、`{ALT}`、`{WIN}`、`{F1}`～`{F24}`、`{ENTER}`、`{ESC}`、`{TAB}`、`{SPACE}`、`{BACKSPACE}`、`{DELETE}`、`{UP}` 等。支持 `{LCTRL}` / `{RCTRL}` 等左右修饰键，以及 `{KP_0}`～`{KP_9}`、`{KP_ADD}` 等小键盘键。多个按键使用 `+` 连接，如 `{CTRL}+{ALT}+{DELETE}` 或 `a+b+c`；它们表示同时按下，不能将 `abc` 当作文字序列输入。加号本身写为 `{+}`，例如 `{CTRL}+{+}`。分隔符两侧可有空格，空格键请写为 `{SPACE}`。

字母和控制键名称不区分大小写，`a` 与 `A` 报文相同；需要 Shift 时显式填写 `{SHIFT}+a`。符号按照美式键盘位置转换，`{+}` 对应 Shift + 等号键。报文格式参照 [USB HID 规范 B.1](https://www.usb.org/sites/default/files/hid1_12.pdf)：第 0 字节为左右 Ctrl/Shift/Alt/GUI 位图，第 1 字节为零，第 2～7 字节为最多 6 个不同的普通键 Usage ID；不足补零、重复键合并。未绑定或语法无效时 `hid_report` 为 `null`。设备端发送按下报文后，统一发送 `00 00 00 00 00 00 00 00` 松开全部按键，不需要逐条配置松键报文。打开工作区时根据 `shortcut` 重新生成按下报文，避免手工编辑后报文与文本不一致；旧配置缺少此字段时默认未绑定，原有 `hid_release_report` 字段会在打开或保存时自动去除。

音频统一输出为 **16 kHz、16 bit PCM、单声道 WAV**。设备不支持直接采集 16 kHz 时，自动使用设备默认采样率采集，并通过已有 scipy 做抗混叠重采样。音频文件名包含时间和随机标识，避免覆盖。关键词目录使用 `keyword1`、`keyword2` 等稳定名称，新增时取现有编号的最大值加一，不因编辑文本、删除其他行而改变。旧工作区中由随机 ID 命名的目录会在打开时自动迁移，原内容保留。

录音在后台线程中进行。每次打开麦克风后先丢弃前 400 ms 输入，再开始计时、显示波形并采集设定时长，因此保存的 WAV 仍为设定时长。完成前只写入临时文件，成功后才发布为 WAV；取消、设备异常或输入溢出时丢弃不完整文件。强制终止进程可能留下 `.recording` 临时文件，不计入素材数量。首次使用请允许系统麦克风权限。波形表示实际输入信号，应用不会把采集到的声音强制置零。

将示例中的 WAV 路径和训练日期目录替换为实际文件。Bash 使用反斜杠 `\` 续行，后面不要加空格；也可以把整个 Python 命令合并为一行运行。切换目录时可使用 `/e/`、`/d/` 等盘符路径；传给 Windows Python 的文件路径使用 `E:/...`、`D:/...` 形式，含空格的路径加双引号。

- 第一个参数：待识别 WAV 的完整路径；支持 PCM16 WAV，多声道转单声道，非 16kHz 音频自动重采样。
- `--model`：ONNX 文件完整路径，直接使用，不拼接源码目录；传入相对路径时以当前终端工作目录为准。模型需为本项目导出的 `stream_external`、`chunk_frames=1` 版本。
- `--config`：可选，默认使用 `src/ds-tc-resnet/config.yaml`。如需使用训练时保存的配置，可在命令末尾追加 `--config "E:/KWS_Custom_UI/workspace/test/training/20261020-185223-845009/config.yaml"`。

脚本推理整个音频文件，保留跨 chunk 的模型状态，最后不足 10ms 的部分补零。每个 10ms chunk 的原始 logits 按类别索引顺序写入所选工作区的 `infer_result.md`，默认是 `workspace/test/infer_result.md`。文件为 Markdown 表格，包含 chunk 序号、音频时间和类别列，每个类别输出 `logits[概率%]`，两者均保留两位小数；每行概率最大的单元格使用 HTML 红色文字高亮，在 Markdown 预览中查看。高亮与消抖使用同一个 top-1 类别，并列最大时取索引最小的类别。每次运行覆盖此文件。概率使用设备端同款稳定 softmax：先减去本 chunk 的最大 logit，再取指数并以 float32 累加归一化，使用未四舍五入的原始 logits 计算。例如：

```markdown
| chunk | time_s | 0:silence | 1:unknown | 2:复制 | 3:粘贴 | 4:确认 | 5:删除 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 0.01 | <span style="color: red;">0.14[18.93%]</span> | -0.05[15.58%] | -0.04[15.71%] | -0.05[15.68%] | 0.07[17.61%] | 0.00[16.48%] |
```

列名和列数来自所选模型的标签。以上为实际测试输出的首行，终端输出示例：

```text
mode: stream_external, duration: 11.644s, chunks: 1165
debounce: warmup=100 chunks, stable=3 chunks, probability>=80%, cooldown=500ms, need_vad_checked=False
[1.00s] 识别结果: 删除 (index=5, probability=83.99%)
logits: E:\KWS_Custom_UI\workspace\test\infer_result.md
消抖识别结果: 删除
```

识别事件随音频时间顺序输出，结束时汇总全部事件；没有关键词通过消抖时显示“未检测到通过消抖的关键词”。结果取决于所选模型与输入音频，上述示例用于说明格式。

`infer.py` 从工作区的 `workspace.json` 读取 `kws_filter`；可通过 `--workspace` 指定工作区，默认使用 `workspace/test`。主界面右下角的“PC端仿真”使用当前工作区最近训练的 ONNX 模型和已选麦克风实时推理，显示同期波形。下方上半区显示仅含索引序号的逐帧 logits[概率]，每行最高概率项以蓝色高亮；下半区只显示通过 KWS 消抖后触发的关键词索引、标签和概率，例如 `[   44.08s] index=5 删除  46.69%`。逐帧文本写入 `workspace/<工作区>/simulation/*.log`。参数在仿真窗口中调整后作用于后续音频帧，并保存到当前工作区。默认配置为：

```json
{
  "kws_filter": {
    "keyword_threshold_percent": 80,
    "cooldown_ms": 500,
    "stable_frames": 3,
    "need_vad_checked": false
  }
}
```

| 配置项 | 默认值 | 范围与含义 |
| --- | ---: | --- |
| `keyword_threshold_percent` | 80 | 0～100 的整数；每个确认帧的 top-1 关键词 softmax 概率至少达到此百分比 |
| `cooldown_ms` | 500 | 最小档 1 ms，其后为 10～1000 ms、步长 10；关键词上报成功后的全局冷却时间 |
| `stable_frames` | 3 | 1～50 的整数；同一类别需连续满足的帧数，每帧 10ms |
| `need_vad_checked` | false | 布尔值；true 时，每个关键词确认帧还需 VAD 判为语音 |

滤波逻辑移植自设备工程 `kws_stream_state.hpp`，流程如下：

1. 每个 10ms chunk 取得所有类别的原始 logits，选出 top-1，并通过稳定 softmax 计算概率。非法数值会清除候选连续计数。
2. 启动后固定预热 100 个有效 chunk（1 秒）。预热期间可累计稳定帧，但不提前上报；该常量与设备一致，不属于上面的四项可调参数。
3. 对关键词（index≥2），逐帧检查 VAD 条件、全局冷却、重复类别和概率门限。任一条件不满足即清除候选计数；类别变化后从 1 重新计数。同一类别连续满足 `stable_frames` 且预热结束时确认上报。
4. 成功上报关键词后进入全局冷却，冷却期间所有关键词都受限，且不累计确认帧。离线推理使用音频时间计时。
5. 连续同类关键词只上报一次，即使冷却结束仍需先确认稳定背景或其他类别才能再次上报。silence/unknown 也使用相同的稳定帧数更新重复抑制状态，但不受概率门限、VAD 条件或冷却限制，也不输出为关键词事件；背景确认不会提前结束已有冷却。

修改 JSON 后重新运行脚本即可生效，启动时会打印实际参数；配置缺失、格式错误或超出范围时会报错。PC 仿真中的参数调整只影响当前 PC 工作区和 PC 推理；仅点击“导入模型到设备”才从本地工作区下发 KWS 参数。设备模式的参数从设备读取，修改后通过 HID 单独写入并持久化。设备使用 AFE 的 `vad_high` 信号；PC 在 `need_vad_checked=true` 时使用本地 Silero VAD v6 的逐帧概率（≥0.5）产生语音标志，仅将已处理完的 32ms VAD 帧映射到 10ms KWS 帧，不读取未来音频。这两种 VAD 来源可能导致不同的门控结果。false 时跳过 VAD 计算。
