# 设备模式与 HID 接口

协议依据为只读参考工程 `E:/USB_Audio_HS2/src/custom/README.md`、`custom_protocol.h`、`tools/kws_control.py`；模型 ABI 与前端分别核对了 `src/kws/model/model_config.hpp` 和 `src/kws/kws_frontend.c`。本项目运行不依赖该工程路径，也不会修改设备工程文件。

## 两种模式

| 操作 | 本地训练 | 连接设备 |
| --- | --- | --- |
| 工作区 | 当前选择的 PC 工作区，重启恢复上次本地工作区 | 固定 `workspace/device` |
| 录音、增删类别、训练 | PC 录音，PC CPU/CUDA 训练 | 隐藏入口并在调用层禁用 |
| 类别文本 | 本地编辑并用于下次训练 | 从设备读取，只读；协议不提供单独改类别的命令 |
| LED、快捷键、flags | 只保存到 PC，编辑不会发到设备 | 读取设备值；编辑后下发到设备并请求保存 |
| KWS 滤波参数 | PC 仿真调节只保存到本地工作区；模型导入时下发 | 从设备读取；滑块或 VAD 开关修改后单独下发并由设备持久化 |
| 模型导入 | 用户点击后，检查当前工作区最近一次成功 INT16 模型并部署 | 隐藏并禁用 |

设备模式的 `workspace.json` 是设备参数的本地镜像，`device.json` 保留设备信息、能力、当前模型及原始绑定快照。进入设备模式首先从设备读取，不把旧镜像自动写回设备。切回本地模式会恢复原来的 PC 工作区；关闭程序仍记忆本地工作区，避免下次把设备镜像当作训练项目。

连接失败或断线时，开关右侧显示红色“连接失败”；可点击该侧或“重新连接”重试。空闲时轮询状态，模型版本或配置版本变化后重新读取完整参数；输入期间不自动覆盖编辑内容。录音、训练和模型传输期间不能切换模式。多台控制 HID 同时连接时拒绝任意选择，需只保留一台待操作设备。

## 通信与参数

使用 `hidapi`，选择 VID/PID `303A:8003` 且 Usage Page/Usage 为 `FF00:01` 的控制接口，不操作键盘 HID。每次打开先用随机 nonce 执行 OPEN_SESSION，验证回显。帧长 64 字节，HIDAPI 写入时在前面加无 Report ID 的 `00`；小端编码，40 字节 payload，CRC32 覆盖前 60 字节。

所有请求串行确认，超时重发原序号及原数据，最多三次。快照分块读取后整体 UTF-8 解码，校验 boot/model/config 版本和 package SHA-256 一致；异步工作线程执行 USB 操作，界面保持响应。

SET_BINDING 严格使用 29 字节 payload，包含 `boot_id/model_epoch/expected_config_revision`、类别 index、flags、RGB、modifier、6 个键位、灯效及按键持续时间。保留从设备读到的持续时间；界面总开关只修改全部行 bit0，每行开关只修改 bit1/bit2。版本冲突时重新读取实际设备状态，不强行覆盖。

SET_KWS_FILTER 使用 17 字节 payload：`boot_id:u32`、`expected_filter_revision:u32`、`keyword_threshold_percent:u16`、`cooldown_ms:u32`、`stable_frames:u16`、`need_vad_checked:u8`，均为小端。固件范围分别为 0～100、1～60000 ms、1～1000 帧和布尔值。命令成功后设备自行写入 NVS，上位机回读 `status.kws_filter` 确认值及 revision；不调用 SAVE_CONFIG。版本冲突时刷新设备值，不覆盖其他客户端的修改。设备模式空闲轮询也会发现外部 KWS 参数变更。

快捷键从 HID 反解为可编辑格式，例如 `{CTRL}+a`、`{BACKSPACE}`。协议允许而界面没有专用名称的键位用 `{HID_XX}` 显示，重新编码不会丢失键位。启用键盘时设备要求至少一个非零普通键位，因此空快捷键或只有 Ctrl 等修饰键不能同时开启键盘开关；界面明确提示。LED 仅支持现有 flash 效果。

参数下发确认后请求 SAVE_CONFIG。升级后的设备不再等待 USB 音频接口关闭即可写 Flash。返回 ACCEPTED 仅表示受理；上位机在后台轮询同一 boot/model/config 版本的状态，确认 `save_pending=false` 且 `config_dirty=false` 后，底部显示“写入完成”。保存失败、版本变化或超时会显示错误，不提前报告完成。设备上电/复位会强制清除三个启用标志，即使曾保存开启状态，也应以实际读回状态为准。这是当前固件约定。

## 模型导入流程

读取本地 `esp32p4-dl/latest.json` 选择成功的 w16a16 模型；验证模型哈希、当前关键词/目录/行映射、类别数/文本长度、单模型未加密 EDL2、容量及模型 ABI/前端说明。模型传输在这些检查通过后才会开始。

随后执行 UPDATE_BEGIN → 完整类别 manifest（对象 0x100）→ 完整模型（0x101）→ UPDATE_COMMIT → ACTIVATE。每个对象传入原始 SHA-256，每块最多 40 字节并确认设备偏移。激活成功且实际包摘要等于 `SHA256(model || manifest)` 后，逐行下发 PC 中的 LED、快捷键及 flags，再请求 SAVE_CONFIG，最后下发本地工作区的 KWS 参数并回读确认。上传前校验设备 KWS 参数范围，不接受旧配置中的 0 ms 冷却或 0 稳定帧。传输失败或取消时尝试 UPDATE_ABORT，释放句柄；不自动覆盖或恢复旧版不匹配绑定。

## 固定模型与前端契约

训练、预处理及导出已固定为参考项目的 `mfcc40_16k_int16_state6_v1`，不能通过配置任意修改拓扑、前端、池化长度或导出 chunk 大小。

| 项目 | PC 训练/导出与设备共用的约束 |
| --- | --- |
| 网络 | 6 个深度可分离卷积块，通道 64/32/32/32/64/64，核 11/13/15/17/29/1，膨胀 1/1/1/1/2/1，残差相加后 ReLU |
| 状态接口 | 6 对 NT1C ExternalState，窗口长度 11/13/15/17/57/98，通道 40/64/32/32/32/64 |
| 池化 | 固定 98 帧滑动窗口平均，不使用累计 sum/count |
| 特征端口 | `streaming/speech_features/normalizer_1/truediv:0`，形状 `[1,1,40]` |
| 分类输出 | `onnx_logits:0`，形状 `[1,类别数]`，类别数 3～34 |
| 状态输出 | `onnx_next_state_1:0`～`onnx_next_state_7:0`；其中第 6 项保留兼容输出但不回灌 |
| MFCC | 16 kHz，480 点窗、160 点步进、FFT512，前 224 个幅度谱频点，固定 Mel80、自然对数下限 1e-12、DCT40、逐系数归一化 |
| 部署精度 | INT16；ONNX 神经后端按参考项目的四维卷积布局导出 |

窗函数、Mel、DCT 和归一化常量直接从参考完整 ONNX 提取，保存于 `src/ds-tc-resnet/data/esp32p4_frontend.npz`，来源及校验和见同名 `.json`。运行时不读取外部参考工程。训练样本为 1 秒有效窗的 98 帧；WAV 流式推理补齐启动历史并产生 100 帧，与设备的零初始化前端一致。

部署前同时校验模型端口名称、各状态形状、分类数量、profile 和前端系数文件 SHA-256。旧版 7 对累计状态/功率谱 dB MFCC 的 checkpoint 明确拒绝接续，需重新开始训练；旧转换产物继续在上传前被拦截，兼容新契约的训练历史可正常接续。

当前 HID 不提供替换前端代码/系数的命令，因此训练固定使用设备已有系数；不能只修改 profile 名称冒充兼容。新模型已通过参考 ONNX 数值对照及本地训练/转换检查，实机加载和识别效果仍应由用户点击模型导入后验证；本次未自动写入设备，也未修改设备工程。

- 当前实机只读验证：成功读取 8 类（2 个背景类 + 6 个关键词）及全部颜色、键位和三个启用标志，设备模式界面显示与原始快照一致。
- 已渲染并检查 1280×900、1100×740 的连接成功界面和红字连接失败界面。
- 模拟 HID 覆盖 CRC、原帧重试、UTF-8 快照、所有允许的键位反解、版本冲突、工作区隔离、录音/训练禁用、完整模型分块/激活/绑定保存顺序、取消中止及不兼容产物上传前拦截。
- 模型上传、参数修改与保存使用模拟 HID 验证；本次没有向真实设备发送 SET_BINDING/SAVE_CONFIG/UPDATE/ACTIVATE，未改变设备模型或配置。
- 实机界面检查前后，对设备工程 `src/` 下 137 个文件计算 SHA-256，内容全部不变。验证明细在本项目 `.qa/device-verification.json`，设备参数镜像在 `workspace/device/`。
